# V4 大模型调用说明

## 是否使用大模型

项目使用大模型辅助生成“文件解析规则”，但大模型不参与 V4 异步导入 Worker 的主执行链路。导入、分片、SKU 校验、幂等写库、错误记录和监控均由确定性代码完成，即使模型服务不可用，已有规则仍可正常导入。

## 调用位置和用途

- 接口：`POST /api/generate-rule`。
- 服务端实现：`src/app/api/generate-rule/route.ts`、`src/lib/llm.ts`。
- 用途：根据 Excel、Word 或 PDF 的结构摘要和本地启发式初稿，生成符合项目 ParseRule DSL 的 JSON 映射规则。
- 不用于：直接生成订单、修改数据库、判断 SKU 是否存在、执行批次或决定任务成功状态。

调用流程为：服务端读取上传文件结构，先生成本地规则初稿，再把结构摘要、目标字段、DSL 约束和初稿发送给 OpenAI-compatible Chat Completions 接口。模型返回 JSON 后通过 Zod Schema 校验；规则仍需在页面试解析并由用户确认，之后才用于导入。

## 发送给模型的数据

为控制上下文和泄露范围，服务端发送压缩后的文件结构：每个表最多前 30 行、每行最多 45 列；纯文本最多 12,000 字符；每页文本最多 5,000 字符。Prompt 还包含目标字段定义、规则 DSL 说明和本地规则初稿。

这意味着样本行可能包含业务字段，因此真实生产应在调用前进一步脱敏手机号、地址和姓名，并与模型服务提供方确认数据保留策略。当前代码不会把数据库连接、QStash/Blob 密钥或 OpenAI API Key 放入 Prompt。

## 配置方式

模型通过以下服务端环境变量配置：

```bash
OPENAI_API_KEY="<server-side key>"
OPENAI_BASE_URL="<OpenAI-compatible base URL>"
OPENAI_MODEL="<model name>"
```

变量没有 `NEXT_PUBLIC_` 前缀，只在服务端读取。真实值配置在本地 `.env` 和 Vercel Environment Variables 中，不写入源码、README 或提交物。

## 输出约束和容错

模型被要求只返回规则 JSON，坐标统一使用 0 基下标，并对低置信度映射写入 notes。服务端先尝试流式 Chat Completions，再使用 AI SDK 结构化输出作为兼容兜底；最终结果必须通过 ParseRule Zod Schema。

如果环境变量缺失、接口超时、网关异常、返回非 JSON 或 Schema 校验失败，接口不会阻断用户工作，而是返回本地结构分析生成的规则，并设置 `aiFallback=true`，同时在 notes 中标记降级原因。用户仍需试解析和确认规则，因此模型输出不是未经检查直接入库的自动决策。

## 与 V4 性能的关系

10,000 行压测使用已确认的解析规则，后台 Worker 不调用大模型。因此压测的 5,929 ms 不包含模型生成耗时，也不依赖模型吞吐。这样可以避免外部模型延迟、限流或不可用影响核心导入 SLA，并让相同文件和规则得到可重复的解析结果。
