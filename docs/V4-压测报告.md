## 生产实测数据（Vercel Blob + QStash）

2026-08-06 在 `https://my-vercel-app-0807.vercel.app` 使用 Neon PostgreSQL、私有 Vercel Blob、Upstash QStash、500 行/批执行：

- 压测任务：`task_43c68c8ccbd4416fb1a7`。
- 文件：10,000 行，1,472,073 字节；客户端直接上传 Blob 2,615 ms，任务 API 490 ms 返回 `202`，从开始上传到拿到 `task_id` 共 3,163 ms。
- 全链路：任务创建到完成 5,929 ms，达到 10,000 行 ≤ 60 秒目标。
- 结果：成功 9,989 行、失败 11 行；失败均为预置非法 SKU，错误码为 `E001`，无 5xx。
- 批次：20 个批次全部完成；批次总耗时 P50 260 ms、P95 457 ms、最大 462 ms。
- 阶段耗时：分片读取 P50/P95 为 50/84 ms，批量校验 38/125 ms，批量写入 130/240 ms。
- 文件准备：单次解析得到 10,000 行并生成 20 个 Blob 分片；随后由 QStash 并发投递批次 Worker。

本次单次任务 API 样本为 490 ms，符合单次 ≤ 1 秒，但单次样本不能替代统计学 P95；提交前若需要严格的 P95 结论，应重复多轮并报告样本分布。大文件本身直接上传 Blob，不受 Vercel Function 4.5 MB 请求体限制；端到端上传时间仍受客户端带宽影响。

该历史结果用于记录优化前瓶颈。后续已修复规则引擎逐行重复展开整表造成的 O(n²) 开销，并改为单次解析后生成分片快照；最终结论以上述生产 QStash 实测为准。本地回退模式的串行 Dispatcher 不代表 QStash 的并发能力。
